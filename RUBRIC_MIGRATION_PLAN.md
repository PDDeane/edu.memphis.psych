# One Rubric, Two Scorers

*lo-blocks · edu.memphis.psych · migration plan*

Move the rubric out of Python and into the OLX, assemble prompts at render time, and keep the
CLI scorer honest as an independent second implementation.

> 70 LLMActions · 23 sheet-bearing · 47 handcrafted — 26 scored items — goal: provably byte-neutral

*Retrieved 2026-08-20 from the artifact published 2026-08-14
(`https://claude.ai/code/artifact/c857865b-2b4b-4fd0-800c-b14e2b5b53e3`) and converted to
markdown. **Not yet executed:** the rubric still lives in `rubric_hN.py` and `olx_prompts.py`
still generates the `<LLMAction>` bodies, so this describes the intended change rather than the
current arrangement.*

## The idea — rubric as content, prose as a function

Today the prompt is **prose generated by Python and baked into the OLX**. The rubric lives in
`rubric_hN.py`; `olx_prompts.py` assembles markdown and writes it into each `<LLMAction>` body.

After: the **rubric is data in the OLX**, and the prompt is assembled by a function when the
action runs. The Python stops being the producer and becomes a second consumer of the same data.

The payoff is not tidiness. Right now the web prompt is produced by the same Python that drives
the CLI, so web-versus-CLI agreement partly measures one generator against itself. Give each side
its own assembler over one shared rubric and the comparison becomes what it was always meant to
be: two independent implementations of one rubric, agreeing or not.

It also makes the engine portable. A new project ships OLX with rubric blocks and needs *no Python
at all* — the CLI exists only where you want the differential test.

---

## Contract — share the data, keep the logic apart

The dividing line follows from the CLI being a test instrument rather than a product. Sharing
logic would make the differential test circular; sharing data is what makes a disagreement
*meaningful* rather than a transcription error.

| Shared — one copy | Independent — deliberately |
|---|---|
| Rubric data (the OLX) | Prompt prose and assembly |
| Slot and rule semantics (`primitives.json`) | Scoring arithmetic |
| Verdict vocabulary (read from `slotSheet.ts`) | Response-schema construction |

**Web** — `assemblePrompt()` in TypeScript, called by `LLMAction` at run time. Snapshot:
`psychology/prompts/web/`, committed and CI-checked.

**CLI · paper scorer** — `score.py` builds its own prompt from the same rubric, in its own words.
Snapshot: `psychology/prompts/cli/`, committed and CI-checked.

Two committed snapshot directories mean every rubric edit produces two reviewable diffs, and a
divergence introduced by editing one assembler shows up in review rather than at the next
agreement run. Nothing pins the CLI's prompt today; this is new coverage, not just relocation.

## Data model — rubric blocks, shared frames, named givens

Non-rendering data blocks, using the `_Noop` renderer that `SetFieldAction` and `PrintAction`
already use:

```xml
<Rubric id="bmod_h1_q6_rubric" item="Q6" max="10">
  <Question>…</Question>
  <Credit what="state_a1" pts="1.25">…</Credit>
  <Deduction code="A_MISMATCH" pts="1.25">…canonical wording…</Deduction>
  <Guidance>…</Guidance>
  <Exemplar label="Full credit — loose phrasing still counts">
    <Given name="Q4a">…</Given>
    <Given name="Q4c">…</Given>
    <Response>…</Response>
    <Verdicts>state_a1=first, change_a1=met, …</Verdicts>
    <Why>…</Why>
  </Exemplar>
</Rubric>
```

### Shared frames are a requirement, not a nicety

`rubric_h2.py` builds its items programmatically — four helper functions, 21 f-strings, and two
shared constants (`_OC_FRAME`, `_EXAMPLE_RULES`) that ten screens draw on. A declarative form
without a library mechanism would duplicate them tenfold and guarantee drift. So `<RubricLibrary>`
plus a reference is load-bearing, and it is the same problem `choices=` solved for categories, one
level up.

### Exemplars stop being course-specific

Today Q6's three exemplars carry fields literally named `four_a` and `four_c` — this course's
assignment structure baked into the schema. They exist for a good reason: Q6 asks the student to
change their antecedents and consequences, so verdicts like `state_a1=first` are unreadable
without showing them.

Named `<Given name="Q4a">` fixes the parochialism, and buys a check that does not exist today. Q6
already declares `context: ['Q1','Q2','Q4a','Q4c']` — the neighbouring answers interpolated for
the *live* student. The exemplar's givens are the same things for the worked example, maintained
separately and agreeing only because a person keeps them agreeing. Key the givens off the declared
context and **a mismatch becomes an error**: an exemplar supplying an undeclared given, or
omitting a declared one, is showing the model a different shape than it will get at run time.

## Proof — three oracles, and why this is provable

Freeze what every prompt says *before* touching anything, then require every stage to reproduce
it. That converts a large migration into a mechanical one — the same discipline
`migrate_verdicts.py` used, where the check was "every slot resolves to the same list, or nothing
is written."

| Oracle | Asserts |
|---|---|
| Web prompt bytes | The TS assembler reproduces all 70 current prompt bodies exactly — the 23 that gain a rubric *and* the 47 handcrafted ones, plus demo content. |
| CLI prompt bytes | `score.py`'s prompt is byte-identical before and after its data source moves. Changing where data comes from must not change what the CLI asks. |
| Corpus replay | Re-scoring a frozen run of the paper corpus yields identical scores. Exercises segmentation, prompt, schema and arithmetic end to end. Known reproducible: a fresh `score.py` already matched a stored run exactly. |

**If all three hold, the migration provably alters nothing about what either system asks any
model.** The acceptance sweep at the end becomes confirmation of a proof rather than the evidence
itself. Wherever a shortcut would break byte-equivalence, the shortcut is the wrong call.

## Risks — each with a mechanical mitigation

Guards, oracles and invariants — never intentions. Several of these are drawn from failures
observed while building the slot-sheet work, and are written here in the shape they actually took.

### R1 · inspectability — the prompt stops being readable in the file

Today you can open the OLX and see exactly what the model is told. Assembling at run time loses
that outright.

**Mitigation.** Do not accept the loss — relocate the artifact. Generated bodies move to committed
snapshot directories, regenerated by script and CI-checked, so `--check` survives in a new form:
*the snapshot is what the rubric assembles*. Plus an inspect route or MCP tool. Hard ordering
rule: the snapshot and inspect tool land *before* bodies are deleted.

### R2 · audit — the equivalence audit's basis shifts under it

Both the prompt comparison and the sheet-rule comparison change shape. Relaxing a check to clear
its output is how detection power is lost quietly.

**Mitigation.** Extend `--selftest` with cases for the new shape *before* rebasing any check.
**20/20 injected breakages is a release gate** — a drop is a blocker, not a trade. When a finding
appears, teach the check the new shape and prove by selftest that it still fires.

### R3 · silent absence — a missing or mistyped rubric produces a plausible wrong answer

An `LLMAction` pointing at a rubric that does not resolve would make a call with no instructions
and return something that looks like an answer.

**Mitigation.** Unresolvable `rubric=` is a content-load error, never an empty prompt. A
sheet-bearing action with neither body nor rubric is an error. And `rubric` goes into the block's
zod schema in the same commit as the parser — `.strict()` silently dropped ten blocks and 40
`<Ref>` children when that step was missed for `choices`/`expect`; the symptom was a hang, not a
message.

### R4 · hand-maintained lists — a registry knows; a hand-written list does not

Two separate failures came from this in one session: `choices`/`expect` missing from
`LLMAction`'s attribute schema (blocks dropped from content), and missing from
`equivalence.py:_sheet_attrs` (the probe reported a sheet's all-satisfied baseline as zero).

**Mitigation.** Add `rubric` to `sheetAttributes` *first* and let the conformance test enumerate
the work. Then one invariant closing both bugs: *for every name in `sheetAttributes`, the block
schema accepts it, `_sheet_attrs` forwards it, and the probe round-trips it.* Derive the Python's
forwarding from the registry rather than listing it.

### R5 · hand-copied payloads — a field added to a type but not to the copy

`readChecks` reconstructed the grader payload field by field. `expect` was added to the type and
to the scoring call, so it typechecked — but was never copied out of the JSON. Every ungated cell
of four items lost exactly that rule's points; one item fell from 17/18 to 4/18; nothing errored.

**Mitigation.** Spread-first then default, on every boundary rubric data crosses. Extend the
round-trip test to rubric fields, including a case for a field the reader has never heard of —
that is what protects the next primitive before anyone teaches the reader about it.

### R6 · compatibility — the majority of LLMActions are handcrafted

47 of 70 are plain prose with no sheet. Compatibility is the common case, not an edge case.

**Mitigation.** A rubric is strictly opt-in: absent one, behaviour is today's, byte for byte. The
legacy path stays *physically separate* — no shared function with an empty rubric, since that is
how a guarantee becomes a bug. Note the subtlety: a handcrafted prompt carrying `slots=` gets
**no** generated checklist today, so the checklist belongs to the rubric path, never inferred from
slots.

### R7 · reproducibility — whitespace and ordering must be exactly reproducible

The byte oracles are worthless if the assembler cannot hit the same bytes.

**Mitigation.** Settle it in stage 1, against the golden bytes, before any content moves. If a
section genuinely cannot be reproduced, canonicalise both sides and declare it then — when it
costs an afternoon rather than a re-migration.

### R8 · interface shape — positional parameters that no longer fit in the head

`scoreSlotSheet` takes eight positional parameters and `satisfiedMap`'s order differs from it. A
caller transposing two gets no error and a wrong score.

**Mitigation.** `assemblePrompt` takes an options object from day one. Stage 1 is the cheap moment
to fold the existing rule-set parameters into a single `Rules` object, since the assembler must
accept them anyway.

### R9 · expressiveness — not every Python construct has a declarative form

H2's rubric is partly computed. Discovering that at stage 3 means redesigning the data model with
items already converted.

**Mitigation.** A required pre-stage-3 audit: inventory every computed construct; for each decide
*library mechanism* or *declared exception that stays in Python*, covered by the dual-read
equality assertion.

### R10 · new coupling — the CLI can no longer run without the content

`score.py` builds from an importable module today; afterwards it needs the OLX.

**Mitigation.** The OLX is in the same repo, so the common case is fine. For the rest, a
`rubric --export` step producing neutral JSON: single *source* without single *location*.

## The limit — what shared data costs, written into EQUIVALENCE.md

Once both implementations read one rubric, a mistake *in the rubric* — a wrong point value, wrong
canonical wording, a guidance bullet that says the opposite of what was meant — is **invisible to
web-versus-CLI comparison**. Both sides will faithfully agree on the wrong thing.

This is the cost of the design rather than a defect in it, and it must not be rediscovered as a
surprise. **A deliverable of this plan is a new section in `EQUIVALENCE.md`** stating the limit
and what actually defends against it, in order of strength:

- **Agreement against the human-graded gold corpus.** The only check anchored outside both
  implementations, and therefore the primary defence against rubric content errors.
- **The two committed prompt snapshots.** A rubric edit produces reviewable diffs on both sides;
  review is a real control, not a formality.
- **`--enforcement`'s probe path**, which compares against the CLI's *measured behaviour* rather
  than its rubric, so it still detects logic divergence where data is shared.

The section should say plainly that green web-versus-CLI agreement is *not* evidence the rubric is
right — it never was, but it is more obviously not once the data is shared.

Two further additions to the deviations register while it is open: each entry should say **which
side does what** rather than only that they differ (the entries corrected this session were stale
precisely because they described an intention), and the `DECLARATION STALE` check keeps them
honest.

## Sequence — eight stages, each with a gate

Stages 0–3 touch nothing live and are reversible. Stage 4 is the first run-time change. Stage 5 is
where the dependency actually inverts.

**00 · Oracles and registry** — *no behaviour change*
Freeze all 70 web prompts and the CLI's prompts as golden. Add `rubric` to `sheetAttributes`.
**Gate:** conformance test enumerates every consumer needing work.

**01 · The assembler** — *no behaviour change*
Pure leaf module, options object, no block or React imports — the discipline `slotSheet.ts`
already follows.
**Gate:** reproduces all 26 generated bodies byte-exact from hand-built structures.

**02 · Rubric blocks, library, named givens** — *no behaviour change*
Plus the expressiveness audit (R9) and the exemplar/context validation.
**Gate:** one item byte-equal, assembled from OLX.

**03 · Migrate 26 items' rubric data** — *no behaviour change*
Scripted, idempotent, refusing to write unless every item still assembles to its golden. Two
copies exist and are checked equal.
**Gate:** all 26 byte-equal; second run reports no edits.

**04 · Web assembles at render** — *runtime change*
Rubric present → assemble; absent → body verbatim. Bodies still present for comparison.
**Gate:** live prompts identical to bodies; handcrafted 47 untouched.

**05 · Python inverts, in three steps** — *runtime change*
**5a** read both sources and assert equal · **5b** build from OLX · **5c** delete the Python
rubric data. At no point is there one unverified copy.
**Gate:** CLI prompt bytes unchanged · corpus replay identical · no-rubric-constants guard passes.

**06 · Retire the generated bodies** — *runtime change*
Delete from the OLX; snapshots and the inspect tool become the readable artifact; rebase the
audit; add the EQUIVALENCE.md limit section.
**Gate:** selftest ≥ 20/20 · snapshots committed before deletion.

**07 · Acceptance**
Three-run sweep. Because the bytes never changed, this confirms a proof rather than supplying the
evidence.
**Gate:** no movement beyond each item's known spread.

---

## Open — one decision worth taking early

Whether the CLI must be able to run with *no OLX present at all*. If yes, the `rubric --export`
bundle from R10 becomes a first-class artifact rather than a fallback, and stage 5 targets the
bundle rather than the OLX directly. That choice shapes stage 5 and should not be discovered late.
